## ADDITIONS

- A-E1-1 (perf, not fixed): `src/app/codex/_components/codexData.ts` imports `cardPath`/`nerfPath` from `src/lib/cardCodex.ts`, which statically imports `ALL_BUFFS` and `ALL_NERFS`. So the card libraries are already in the /codex client chunk and the browser's `Promise.all([import(...)])` "async chunk" buys nothing. Fix: move `cardPath`/`nerfPath` (pure id to path) into a library-free module and import that from `codexData.ts`. Needs a bundle measurement before and after; wave 2.
- A-E1-3 (measurement, affects every slice): in this sandbox `local("Arial")` does not resolve (fontconfig maps the name Arial to Liberation Sans for `font-family`, but `@font-face src: local()` matches full or PostScript names only), so next/font's "Noto Sans Fallback" face (size-adjust 106.33% over Arial) falls through to a narrower default: 583px for a 15px test line against 681px for Noto Sans and 640px for Arial (`scripts/.e1tmp/fontw.ts` style probe). Text wraps one line longer before the web font lands, which is most of the CLS on text-heavy pages here: /faq 0.08 / 0.17, /terms-of-service 0.12 at 1280, /codex/buff/pawn_push 0.21 / 0.26, /about 0.036 at 390, /updates 0.027 at 1280 (`evidence/E1/content-cls-sweep.txt`), every one a single shift at the moment `document.fonts` turns loaded. On a device with Arial the fallback metrics match within about 0.1%, so these are sandbox artifacts, not route bugs; E1 left them. See REQUESTS (integrator).
- A-E1-2: the /codex first frame still has a 0.0034 shift (the h1 moves 3px as the fonts swap) and the header chip's 0.001 (slice A). Font metrics are root layout (A/I).
