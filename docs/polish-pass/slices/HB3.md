## How it was measured

- Before: bundles built from c383949 (the tree when this track started, with HB1's and HB2's landed engine), kept in the scratchpad, run by the same committed test scripts through `--bundle` / `ITEST_BUNDLE` / `--entry`. After: the bundles built from this track's commits. Local ports only (8872-8874 engine, 8898-8899 arena); nothing talked to a production host and nothing was deployed.
- Every command ran through `scripts/polish/heavy.sh nice -n 10`. The box was heavily loaded by other agents during parts of the runs (load average 14 to 50 on 4 cores), which is noted where it matters.

## ADDITIONS

- Module duplication under tsx in the `"type": "module"` service packages: a `.ts` test inside `engine-service/` or `arena-service/` run with tsx loads the engine twice, so module state such as `setDraftPoolOverrides` set by the test never reaches the copy `game.ts` rolls offers from (the first overrides fixture silently showed 0 divergence). `engine-service/test/package.json` marks the test directory CommonJS like `src/`, and the arena tests bundle with esbuild the way the arena ships. Worth knowing for anyone adding scripts under those two directories.
- The engine reply gains `depth` (completed ply, server to server only) beside `scoreCp`, so the load test can report depth per concurrency.
- Em dashes removed from comments across `arena-service/*.ts`, `engine-service/README.md` and `engine-service/deploy/*` (comment and documentation text only).

## REQUESTS

- To slice H or the integrator (`worker.ts`), R3 as planned, with the shapes the service now accepts: in `remoteHouseMove` add `persona: persona.userId` (the caller has it), `incrementSec: match.setup.incrementSec` and `deadlineMs: HOUSE_ENGINE_TIMEOUT_MS - 700` to the body, and read `{ move?: Move | null; scoreCp?: number | null }` (ignore `depth`). `scoreCp` is from the mover's side and null when the move did not come from a search. Also treat a 503 like any other non-OK answer (local fallback, already the case). Additive in either deploy order.
- R10 is now useful: add `...(match.cardOverrides ? { cardOverrides: match.cardOverrides } : {})` to `serializeMatchForEngine` in `worker.ts`. The service sanitizes it and applies it to draft matches only.
- R12, the arena half: return the DO-seated persona ids from `/arena/games` as `seated: string[]` in the JSON reply (`handleArena`, `return Response.json({ enabled, lobby, watch, seated })`), where `seated` is the `bots.w` / `bots.b` ids of every live DO house match. The arena excludes them from filler seating; an older arena ignores the field.
- R14 (new, P20): so the arena can roll filler drafts without Chess Diff, every consumer that re-rolls its offers must apply the same pool. (a) `worker.ts`: add `cardOverrides?: DraftPoolOverrides` to the `ArenaSnapshot` and `ArenaEndRecord` types in `worker.ts`, and in `buildExternalMatch` set `...(snap.cardOverrides ? { cardOverrides: sanitizedOverrides(snap.cardOverrides) } : {})` on the returned match, so `replayForward` installs it for the replica; the end frame's rebuild from an `ArenaEndRecord` must install `record.cardOverrides` the same way. (b) `src/app/api/arena/end/route.ts:87-93`: pass `rec.cardOverrides` into the archived draft record (`draftRecordFromMatch` already archives `cardOverrides` for DO matches). Then set `ARENA_EXCLUDE_FILLER_CARDS=true` in `/etc/nerfchess-arena.env` on the box. Until both land the flag must stay off.
