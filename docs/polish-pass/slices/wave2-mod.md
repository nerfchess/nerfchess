# Wave 2, area mod

Every probe ran against the shared dev server on :3000 through `scripts/polish/heavy.sh`, with the seeded `polish_mod` session (a moderator, not an admin) unless a row says otherwise. The dev server restarted once during the runs; the probes were run again after it came back. The "Before" column is the audit's measurement from the finding. The "After" column is from this pass.

## Notes per finding

**1. Session check.** Root cause: `fetchMe()` returns `undefined` for "the request failed" and the pages read `undefined` as "still loading", with no retry. Class: a tri-state answer (unknown, signed out, user) collapsed into two. Fix: new `src/components/mod/ModGate.tsx`. `useModGate()` reads the user from `useSession()` (so the pages share the header's single /me request, as asked of route slices in wave 1), calls `fetchMe()` only while the answer is unknown, and flags a failure when that call comes back `undefined`. `ModGateNotice` draws the three states: Loading, the failure line with Retry, and "This page is for moderators." with a Sign in link that returns to the current path. All five gates now use it (the console, the card editor, the house editor and `StatsShell` for the three stats pages). Siblings: `grep fetchMe src/app/mod src/components/mod` now finds only the hook.

**2 and 3. Card editor.** Root cause of 2: `loadOverrides` returned quietly on a non-ok answer, so the map stayed empty and a draft built from it had blank fields and `enabled: true`. Class: a failed read treated as "no data" before a write. Fix: the overrides load has its own state; while it is loading the table waits, and when it fails the table is replaced by an error with Retry, so there is no Edit button to press. A later reload that fails also closes any open draft. Root cause of 3: `setBusy(false)` sat after an `await fetch` with no `try/finally`. Fix: both Save and Reset use `try/catch/finally`; a network error leaves the draft open and says so in a `role="alert"` line. The house page's `post()` already used this shape.

**4. Section failures.** Root cause: fetch chains with no else and `catch(() => {})`. Class: a list whose failure looks like loading (or, for players, like "No players match"). Fix: a shared `LoadFailed` in `src/components/mod/ui.tsx` (message plus Retry, `role="alert"`) in the audit log, player ideas, nerf and buff verdicts. The house controls show an inline failure with Retry and "-" in place of "…". The same class was in three more sections that the audit did not list, fixed the same way: reports and chat flags (a queue that never loaded now says so; a list already on screen stays after a failed reload), and players (a failed search no longer reads as "No players match that search", and a failed history load says so with Retry instead of "Loading history…"). Left alone: the god panel toggle (owner-only) still shows its unknown state if its GET fails; its POST already reports errors.

**5. Layout shift.** /mod#controls: the tier strength editor is 784px tall at 1280 and 3,774px at 360 (20 tiers), and it mounted after the fetch above the Notifications section. Holding that much blank space while loading would be worse on a phone, so the editor is now a disclosure (`<details>`) drawn from the first frame and closed on load. Its summary line reads "Strength by tier" plus "20 tiers, all default" or "N of 20 tiers tuned" once loaded. The editor's controls and behaviour are unchanged inside it. This changes how the mod console lays out the house controls, not how the bots play or appear publicly (owner directive 2). /mod#games: the stat grid is drawn from the first frame with the same seven labels and "…" values, "Guests created" is always a tile, and "Most played mode" always has a sub line, so the grid's height does not change when the numbers land. A failed stats call now shows "-" and a line instead of a missing block. In `StatGrid`'s phone rows the value column has a 45% floor and block children, so a value that replaces "…" does not move sideways (0.0173 to 0.0083 at 360). This also applies to the dashboard and stats grids; they measured 0.0002 to 0.0004 after.

**6. axe.** The inline Codex link now uses the repo's in-text link style (`underline underline-offset-2`). It sits in a sentence, so it falls under the target-size inline exception. The games-per-day scroller has `tabIndex={0}`, `role="region"` and an `aria-label`. Siblings: the other `overflow-x-auto` wrappers in the mod area either contain controls (cards table, feedback table headers, the tier table inputs) or never overflow where they show (dashboard table, per its comment), and axe found nothing on them at 360 or 1280.

**7. Audit log.** The route takes `group` (the chip groups; SQL `CASE` that mirrors `kindOf()`, commented in both places), `q` (LIKE over mod, target, action, note and reference, with `%` and `_` escaped), and a `before`/`beforeId` cursor. It returns 100 rows plus `next`. `?kind=` still works. The section debounces the search by 300 ms, asks the server, and offers "Load older". The empty state reads "Nothing in the whole log matches that filter." Checked on the local log (18 rows): a cursor taken from the middle row returns exactly the rows after it, a mod-name search returns only matching rows, `q=%_` answers 200, and the six groups add up to the full log (mute 1, warn 7, queue 10). The local log is too short to show a second page; the cursor check covers the same WHERE clause.

**8. Persona link.** `PersonasLink` no longer takes `isAdmin`, and `ControlsSection` dropped the prop. Checked in the same probe and in `mod-ui-check.ts` F129.

**9. Archive cursor.** The same tiebreak as the audit log cursor. A client without `beforeId` gets the old `completed_at < ?` behaviour.

**10. House page.** Uses the shared gate (so it gets the Sign in link and the /me Retry), and fetches the roster in an effect keyed on `isMod`.
